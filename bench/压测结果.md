# 大麦项目压测记录（2026-09-22，已校验版）

## 环境
- 本机单机：MySQL 8 / Redis / Nacos 2.3.2 / Kafka 3.9.1 / ES 7.17.25（后三个为 Docker 容器），与 6 个微服务同机
- 压测脚本：Node 直连 program-service(6086)，绕开网关验签；预热 300 次后持续 20 秒
- 校验规则：响应必须为 HTTP 200 + `"code":"0"` + `data` 非 null 才计入有效，否则单独统计

## 有效数据结果（并发 100，20 秒）

| 接口 | QPS | 平均 | P50 | P95 | P99 | 有效率 |
|---|---|---|---|---|---|---|
| /detail（V1 纯 Redis 缓存） | 1154 | 87ms | 86ms | 107ms | 125ms | 23128/23128 = 100% |
| /detail/v2（多级缓存：Caffeine+Redis+DB） | **6741** | 15ms | 14ms | 27ms | 34ms | 134898/134898 = 100% |

多轮运行区间：V1 约 840~1150 QPS；V2 约 4800~6700 QPS（受 JVM 预热影响）

## 被剔除的无效数据
- `/local/detail`：调试端点，读的本地缓存 key（"4"）与 v2 写入 key（"d_program:4"）不同，永远返回 data:null。
  此前测出的 6439/6689 QPS 全是空响应，作废。
- 教训：压测必须校验响应体，只数 HTTP 状态码会把错误响应当成有效吞吐。

## 简历口径（诚实版）
